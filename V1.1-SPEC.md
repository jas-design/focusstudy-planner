# FocusStudy V1.1 Specification

## 1. V1.1 Goals

FocusStudy V1.1 is a planned product evolution after the functional V1.0 release. This document is a planning artifact only. It does not authorize production implementation until a later phase.

Primary goal:

- Make FocusStudy feel warmer, softer, more student-friendly, and more emotionally comfortable for daily use.

V1.1 should preserve the V1.0 product promises:

- One standalone offline HTML file.
- No account, install, server, network dependency, CDN, analytics, or tracking.
- Vanilla JavaScript, SCSS, semantic HTML, LocalStorage, and JSON backup/restore.
- Simple, maintainable, local-first code.
- WCAG 2.2 AA direction, visible focus states, keyboard access, and responsive layouts.

V1.1 should move the experience from "calm student dashboard" toward "cozy productivity workspace" without becoming decorative, crowded, or gamified.

## 2. Benchmark Findings

### Source Notes

Reference product requested:

- Etsy listing: `https://www.etsy.com/listing/4524073297/adhd-life-planner-web-app-all-in-one`

The exact Etsy listing page could not be reliably inspected through the available browser tooling. No screenshot image file was present in the attachment folder for this prompt; only the pasted request text was available.

An indexed Etsy search result for a closely related ADHD planner web app provided public benchmark information: an all-in-one interactive browser planner with focus mode, brain dump, habit tracking, medication tracking, Pomodoro timer, time-blindness support, insights, planning, wellness, leisure, home/lifestyle, finances, and export backup. This specification uses the requested prompt description and indexed listing information for high-level competitive analysis only.

Do not copy the benchmark product, its branding, proprietary copy, exact interface, or broad life-management scope.

### Visual Takeaways To Adapt

- Softer emotional tone: warm blush/ivory backgrounds, white surfaces, soft pink accents, and friendly copy.
- Compact cards: smaller cards with 12px to 20px padding and soft but restrained radius.
- Clear dashboard chunks: useful summary cards are compact and immediate, not oversized SaaS metrics.
- Friendly density: more visible useful information in the first viewport without feeling busy.
- Focus Mode utility: the benchmark concept appears to combine a timer with current task context and support tools rather than showing only a huge timer.
- Student-friendly language: headings should feel supportive and specific, not corporate.

### Visual Takeaways To Avoid

- Broad life-management scope unrelated to students.
- Medication, health, bills, budget, meals, cleaning, household, panic, or medical-style tools.
- Overly colorful feature sprawl.
- Copying proprietary words, app names, feature labels, or exact screen composition.
- Turning FocusStudy into an all-purpose adult life planner.

### Typography Benchmark

Exact font not verified.

The benchmark appears to rely on rounded, friendly visual proportions rather than sharp enterprise typography. FocusStudy should recreate only the proportion and warmth, using offline-safe system font stacks.

## 3. Visual Changes

V1.1 should soften the current visual system while preserving the established FocusStudy identity.

Recommended direction:

- Move light mode from warm parchment/coral toward a softer ivory/blush workspace.
- Reduce the visual weight of the Today hero.
- Reduce oversized timer and dashboard typography outside active Focus Mode.
- Use compact summary strips and calm rows before large panels.
- Keep task rows as the core planning component.
- Make cards more useful and less empty.
- Keep shadows subtle and secondary to borders and tonal surfaces.
- Use friendly microcopy, but avoid motivational clutter.

The product should feel:

- Warm.
- Welcoming.
- Student-oriented.
- Quiet.
- Useful.
- Lightweight.

It should not feel:

- Corporate.
- Analytics-heavy.
- Medical.
- Childish.
- Decorative at the expense of clarity.

## 4. Typography Ratios

V1.1 should tighten the type scale so Today, Progress, and idle Focus screens do not feel oversized.

Recommended scale:

| Role | Target Range | Notes |
| --- | ---: | --- |
| Metadata / microcopy | 11px to 12px | Due dates, labels, counts, helper text. |
| Small | 13px to 14px | Secondary row text and low-emphasis body copy. |
| Body | 14px to 16px | Primary readable interface text. |
| Card heading | 16px to 18px | Assignment cards, course cards, compact panels. |
| Section heading | 18px to 22px | Top 3, Today's Tasks, Weekly Plan sections. |
| Page title | 28px to 34px | Main route titles. |
| Large greeting | 32px to 40px maximum | Today greeting only, not a large hero block. |
| Focus timer | 56px to 72px | Active Focus Mode, responsive by viewport. |

Font direction:

```css
font-family:
  ui-rounded,
  "SF Pro Rounded",
  "Segoe UI",
  system-ui,
  -apple-system,
  BlinkMacSystemFont,
  sans-serif;
```

Implementation notes:

- Evaluate `ui-rounded` in Chrome and Edge before committing it.
- If browser differences are too large, use the existing stable system sans stack and soften the interface through weight, spacing, and color.
- Do not add Google Fonts or external font files.
- Preserve the monospace timer stack only where stable numeric alignment matters.
- Do not scale normal text directly with viewport width.

## 6. Layout Changes

V1.1 should increase useful information density slightly.

Global layout recommendations:

- Keep the desktop sidebar, but group navigation by purpose.
- Keep the app shell quiet and secondary to the planning area.
- Reduce empty card height on Today and Focus idle.
- Keep main content readable at 720px to 960px, with optional context zones only when useful.
- Prefer sections, rows, and compact tool panels over a full grid of equal cards.
- Keep mobile as a dedicated single-column experience.

Card proportions:

- Internal padding: 12px to 20px for most compact cards.
- Radius: 12px to 18px, reusing tokens where possible.
- Border: subtle semantic border.
- Shadow: minimal; use only for modals, elevated overlays, or repeated cards that need separation.

Do not put cards inside cards.

## 7. Today Changes

V1.1 Today should replace the oversized greeting hero with a compact daily planning opening.

Recommended order:

1. Greeting.
2. Supportive sentence.
3. Compact summary.
4. Energy.
5. Today's One Thing.
6. Top 3.
7. Today's Tasks.
8. Upcoming.
9. Exams.

Suggested desktop structure:

```text
Good afternoon, Alex.
Pick one small next step. You do not need to plan the whole week at once.

[ Tasks completed ] [ Focus today ] [ Current streak ]

Energy
[ Low ] [ Okay ] [ Good ]

Today's One Thing
[ linked assignment / empty action ]

Top 3
Today's Tasks
Upcoming
Exams
```

Rules:

- Do not create ten widgets.
- Keep the strongest emphasis on the next useful action.
- Summary metrics should be compact and derived from real user data.
- No fake production statistics.
- Empty states should invite action without making the user feel behind.

## 8. Focus Mode Changes

V1.1 should make Focus Mode more useful than a timer-only screen while preserving the corrected V1.0 state architecture:

- Focus idle: normal application shell with navigation.
- Active Focus: dedicated distraction-reduced Focus Mode.

Recommended active desktop layout:

```text
Focus Mode

[ Sessions Today ] [ Focus Minutes ] [ Current Streak ] [ This Week ]

LEFT
Focus Timer
25:00
Pause / Resume / Complete

RIGHT
Working On
Assignment
Current Step
Session Goal
Distraction Catcher
[ Random thought... ] [ Park it ]

Recent Sessions
```

Focus Mode principles:

- Timer remains visually important but not isolated.
- Current assignment and current step should explain why the session exists.
- Session goal is optional and short.
- Distraction catcher should support the session without interrupting it.
- Recent sessions should be lightweight and calm.
- Do not reintroduce a navigation dead end.
- Do not make active mode look like a business analytics dashboard.

Focus session metrics:

- Sessions Today: completed focus sessions for the local calendar day.
- Focus Minutes: completed focus time for the local calendar day.
- Current Streak: same simple activity streak rule as Progress.
- This Week: completed focus time for the current week, formatted cleanly.

All values must be derived from stored source data.

## 9. Energy

Add an optional current-energy selector on Today.

Options:

- Low.
- Okay.
- Good.

Purpose:

- Help the student choose a suitable kind of work.
- Encourage realistic planning.
- Support prioritization without making medical or psychological claims.

Storage:

- Store by local date.
- Store only the selected value and timestamp.
- Do not infer health, mood, diagnosis, or productivity score.

Suggested data shape:

```json
{
  "date": "2026-09-22",
  "energy": "okay",
  "updatedAt": "2026-09-22T12:00:00.000Z"
}
```

Allowed values:

- `low`
- `okay`
- `good`
- `null`

## 10. Today's One Thing

Add a single daily assignment focus separate from Top 3.

Purpose:

- Answer: "If I finish one important item today, what should it be?"
- Give an overwhelmed student one clear anchor.

Rules:

- Store an assignment ID, not a duplicate assignment object.
- One Thing can be cleared or changed.
- If the linked assignment is deleted, show a safe empty fallback.
- If the linked assignment is completed, show a completed state and offer to choose another.
- Do not count One Thing as one of the Top 3.

Suggested data shape:

```json
{
  "date": "2026-09-22",
  "assignmentId": "assignment_abc123",
  "updatedAt": "2026-09-22T12:00:00.000Z"
}
```

## 11. Distraction Catcher

Add a quick capture field during active Focus Mode.

Purpose:

- Let the student park an unrelated thought without stopping the timer.
- Reduce context switching.

Rules:

- Input is short and fast.
- Pressing "Park it" should not pause, complete, or reset the timer.
- Distractions should remain attached to the session initially.
- At session end, the user may move selected distractions to Brain Dump.

Suggested active session field:

```json
{
  "distractions": [
    {
      "id": "distraction_abc123",
      "text": "Email professor after this session",
      "createdAt": "2026-09-22T12:15:00.000Z",
      "movedToBrainDumpId": null
    }
  ]
}
```

Completed sessions should preserve distractions as historical notes unless moved to Brain Dump.

## 12. Session Goal

Add an optional short goal before starting a Focus Session.

Examples:

- "Finish introduction draft"
- "Review lecture notes for 20 minutes"
- "Complete source outline"

Rules:

- Optional.
- Plain text only.
- Store on active and completed focus sessions.
- Keep max length modest, such as 120 characters.
- Do not require a goal to start.

Suggested field:

```json
{
  "sessionGoal": "Finish introduction draft"
}
```

## 13. Weekly Plan

Add a dedicated Weekly Plan view focused on school planning, not a full calendar.

Purpose:

- Show the current academic week.
- Combine class blocks, important assignments, and exams.
- Help students understand "what is coming this week" without building a calendar app.

Desktop structure:

```text
Weekly Plan

Week controls

Monday | Tuesday | Wednesday | Thursday | Friday | Saturday | Sunday
Classes
Important assignments
Exams/deadlines
```

Mobile structure:

```text
Weekly Plan

[ Week selector ]

Monday
Classes
Assignments
Exams

Tuesday
...
```

Rules:

- No drag-and-drop in V1.1.
- No month view.
- No external calendar integration.
- No reminders or notifications.
- Use existing course, assignment, and exam data.
- Do not squeeze a seven-column timetable into 390px.

## 14. Class Schedule

Extend Courses with optional schedule information.

New optional fields:

```json
{
  "schedule": [
    {
      "id": "schedule_abc123",
      "days": ["monday", "wednesday"],
      "startTime": "09:30",
      "endTime": "10:45",
      "location": "Science Hall 204"
    }
  ]
}
```

Rules:

- Courses must still work without schedule data.
- Meeting days are optional.
- Start and end time are optional as a pair, but if one is provided, validate the other.
- Location is optional and short.
- Multiple meeting blocks per course should be supported, because college courses may have lecture/lab patterns.
- Weekly Plan reads schedule blocks from courses.

## 15. Grades

Add a simple Grade Tracker linked to Courses.

Purpose:

- Give students a practical place to record assessment scores.
- Avoid advanced GPA or weighted-grade complexity in V1.1 unless it remains very simple.

Course grade fields:

```json
{
  "currentGrade": "B+",
  "assessments": [
    {
      "id": "assessment_abc123",
      "title": "Midterm",
      "score": 86,
      "scoreType": "percent",
      "date": "2026-10-15",
      "notes": ""
    }
  ]
}
```

Rules:

- Store per course.
- Support percent score first.
- Allow optional notes.
- Display current grade as user-entered text, not computed GPA.
- Future weighted calculation can be a later enhancement.

## 16. Notes

Add simple course-linked notes with a Cornell-style structure.

Fields:

```json
{
  "id": "note_abc123",
  "courseId": "course_abc123",
  "title": "Photosynthesis lecture",
  "cueQuestions": "",
  "notes": "",
  "summary": "",
  "createdAt": "2026-09-22T12:00:00.000Z",
  "updatedAt": "2026-09-22T12:00:00.000Z"
}
```

Rules:

- Plain text only.
- No rich text editor.
- No markdown requirement.
- Notes can be linked to a course or left uncategorized if needed.
- Course deletion should not delete notes by default; notes should fall back to "No course" unless the user explicitly deletes them.

## 17. Habits

  "active": true,

Rules:

- Simple streak is allowed.
- No complex levels, reward shop, badges, or full life-management habit platform.
- Habits should live under Growth navigation, not dominate Today.
- Today may show a compact habit preview only if it does not crowd student work.

## 20. Mobile Behavior

V1.1 mobile must be designed, not squeezed.

Today mobile:

- Greeting and short support line.
- One Thing.
- Energy.
- Top 3.
- Today's Tasks.
- Upcoming and Exams lower on the page.
- Summary metrics compact and optional if space allows.

Focus mobile:

- Active timer first.
- Current assignment and step second.
- Goal and distraction catcher below.
- Metrics collapsed into a compact row or disclosure.
- No horizontal scrolling.

Weekly Plan mobile:

- Day-by-day stacked agenda.
- Week controls at top.
- Each day shows classes, assignments, and exams in separate small groups.
- Seven-column timetable is desktop/tablet only.

Grades mobile:

- Course cards with current grade and assessment list.
- Avoid dense tables.

Notes mobile:

- Course filter.
- Note list.
- Edit form uses full-width textareas.

Habits mobile:

- Simple checklist by day.
- Streak text only if useful.

## 23. Migration Requirements From V1.0

Migration must be safe, automatic, and non-destructive.

Required migration behavior:

- Load existing `focusstudy:v1:data`.
- If `version` is `1`, normalize to version 2.
- Preserve all existing courses, assignments, subtasks, brain dump items, priorities, exams, focus sessions, settings, and user data.
- Convert existing `dailyPlan` into a `dailyPlans` array entry when it contains useful data.
- Add `energy: null` and `oneThingAssignmentId: null` to migrated daily plan records.
- Add `schedule: []`, `currentGrade: ""`, and `assessments: []` to every course.
- Add `sessionGoal: ""` and `distractions: []` to active and completed focus sessions when absent.
- Add root arrays `notes: []` and `habits: []`.
- Keep deleted-reference fallbacks safe.
- Preserve corrupted-data recovery behavior.
- Preserve backup validation before replacement.

Migration testing:

- Empty V1.0 data.
- V1.0 data with courses and assignments.
- V1.0 data with active focus session.
- V1.0 data with completed focus sessions.
- V1.0 data with corrupted or partial fields.
- V1.0 backup import into V1.1.
- V1.1 backup export and restore.

Do not remove V1.0 data fields until the V1.1 app can reliably read and write the new shape.
